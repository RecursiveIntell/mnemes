# Lane 2 — Mnemes Transport, Receiver, Bootstrap, and Sender Runtime

> **For Hermes:** Own Mnemes control-plane and network runtime files exclusively. Use semantic-memory public APIs; never reproduce its SQL semantics.

**Goal:** Turn V2 envelopes into an authenticated, durable device-to-server replication path with exact-byte retries, restart-safe ACKs, bootstrap generation promotion, and explicit status interfaces for search.

**Architecture:** Keep V1 fact-create as a canary route. The generic V2 handler performs strict decode → signature/admission → sequence decision → semantic owner apply → durable ACK. The sender uses its own SQLite spool because queue semantics must preserve contiguous per-stream watermarks and exact bytes.

**Files owned:**
- `mnemes-replication/src/replication/**` except Lane 3’s dedicated claim-component module
- `src/client/**`, `src/bin/mnemes-sync-agent.rs`
- `src/server.rs`, `src/store.rs`
- `src/replication/bootstrap.rs`
- Mnemes runtime integration tests

**Do not edit:** `Libraries/semantic-memory/**`, claim-ledger/MCP code, `src/shards.rs`, search router tests.

## Task 2.1 — Generalize admission and durable receiver state

1. Add generic device/store/component admission tables and APIs beside V1 fact-create tables; preserve V1 route behavior.
2. Persist public key, principal, scope, role, activation/cutoff, revocation, epoch, and fencing. Never persist a private key.
3. Replace fact-only receiver decisions with component-scoped inbox/stream state retaining exact envelope digest and applied receipt.
4. Bind authenticated bearer/device to signed home device and catalog-selected shard; no client path selection.

**RED:** unadmitted/revoked/wrong-device/wrong-scope/stale-fence envelopes do not change shard content, inbox, or watermark.

**GREEN:** valid exact duplicate returns durable `Duplicate`; same identity/different digest yields `Fork` quarantine.

## Task 2.2 — Add V2 mutation route and owner apply boundary

1. Add `POST /v2/replication/mutations` to `src/server.rs`; keep `/v1/sync*` disabled.
2. Use Lane 0’s strict decoder and admitted-key API only; no verify-with-embedded-key shortcut.
3. Dispatch to Lane 1’s `apply_verified_operation` using a canonical shard resolved by the Mnemes catalog.
4. Persist/return ACK only after semantic apply and receiver inbox/stream decision are durable. If cross-database control metadata cannot be atomic, derive/recover it from the semantic inbox rather than claiming false atomicity.
5. Publish a narrow read-only `ReplicaStatusReader` and notification interface for Lane 4: applied, lexical-visible, ANN-indexed, head, generation, state, and last signed owner report.

**Run:** HTTP integration tests with fresh/reopened replica store; assert durable row and stream head, not status code alone.

## Task 2.3 — Implement sender and exact-byte spool

1. Add `src/client/{config,source,spool,transport,worker,status}.rs` and `src/bin/mnemes-sync-agent.rs`.
2. Read source operations only through Lane 1 export API.
3. Persist raw request bytes, batch ID, component/stream identity, source head, retry deadline, attempt state, and validated ACK; retries resend byte-identical requests.
4. Serialize within a stream, parallelize independent device/store/component streams with bounded permits.
5. Poll source head at one second maximum; emit a signed heartbeat every five seconds; use deadline-aware 250ms/500ms/1s/2s retry while under 15 seconds.
6. Compact only after durable contiguous ACK plus server recovery evidence and a separately verified local recovery point.

**RED:** kill sender after spool write, after send, after receiver commit before ACK, and after ACK before local persist.

**GREEN:** restart rebuilds state, sends no regenerated bytes, and reaches matching ACK/root.

## Task 2.4 — Bootstrap into paired generations

1. Add bootstrap routes/manifests/pages/verify/promote and control state in `bootstrap.rs`/`store.rs`.
2. Stage into a new generation directory; active generation remains read-only to bootstrap writes.
3. Validate page chains, component roots, claim/blob dependency manifest, schema/coverage versions, and expected source cut.
4. Atomically switch the control catalog and replica tree as one paired generation; retain previous verified generation for rollback.
5. Rotate live stream epoch only after verified cut/promotion, then replay tail.

**RED:** interrupted upload, bad page digest, root mismatch, missing blob, or failed verify never changes active generation.

**GREEN:** fresh complete snapshot plus post-cut live mutation converges to source roots/head.

## Task 2.5 — Runtime status and operational containment

1. Expose per-component sender/receiver state, lag age, sequence/head, spool age/bytes, heartbeats, root status, and typed degradation reasons.
2. Ensure active routes are loopback/tunnel-confined and payload signatures remain mandatory.
3. Add systemd unit/example configuration only with least-authority state/key directories and non-secret logs.
4. Leave V2 disabled by default until Lane 5 canary approval.

## Handoff

Publish server/client configuration schema, status-reader interface, bootstrap fixture, V2 route contract, and verified restart receipts. Lane 4 integrates only against this interface; Lane 3’s component registration is a reviewed, single-owner Lane 2 change.

**Rollback:** stop sender sessions first, quarantine the affected replica generation, restore prior paired catalog/tree and binary/config, retain spool/ACKs/roots, and never alter device-primary data.
